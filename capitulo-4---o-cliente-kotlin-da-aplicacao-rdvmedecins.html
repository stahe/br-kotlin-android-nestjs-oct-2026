    5. Capítulo 4 - O cliente Kotlin da aplicação RdvMedecins

    5.1. Visão geral da arquitetura

    Este cliente se comunica com o servidor [rdvmedecins-nestjs-server] do curso, que permanece totalmente inalterado, pelas mesmas rotas HTTP (POST [/login], GET [/getAllDoctors], GET [/getAllClients], GET [/getDoctorScheduleOfDay/:doctorId/:day], POST [/addAppointment], POST [/deleteAppointment]), com o mesmo envelope JSON [{ status, data }] e a mesma autenticação por token [JWT] (cabeçalho [Authorization: Bearer <token>]).

    // =========================================================================
// RdvMedecinsApplication.kt
// -------------------------------------------------------------------------
// Primeira metade do lib/main.dart da versão Flutter: construção,
// UMA ÚNICA VEZ, dos serviços da aplicação.
//
// Por que uma classe Application? No Android, a tela (a Activity, veja
// MainActivity) é DESTRUÍDA e depois RECRIADA a cada rotação do celular, a
// cada mudança do idioma do sistema, etc. Serviços construídos na
// Activity seriam, portanto, reconstruídos a cada rotação. O
// objeto Application, por outro lado, é criado quando o processo inicia e
// vive enquanto ele durar: é o lugar certo para objetos que devem
// durar toda a vida da aplicação. Ele é declarado no
// AndroidManifest.xml (atributo android:name da tag <application>).
//
// A ORDEM de construção importa, como na versão Flutter:
// AuthService precisa de SettingsService (a URL do servidor); o cliente
// HTTP autenticado precisa de AuthService (o token); AppointmentService precisa
// do cliente HTTP autenticado e de SettingsService.
// =========================================================================

package fr.rdvmedecins.client

import android.app.Application
import android.content.Context
import fr.rdvmedecins.client.core.http.AuthInterceptor
import fr.rdvmedecins.client.core.i18n.TranslationsService
import fr.rdvmedecins.client.core.services.AuthService
import fr.rdvmedecins.client.core.services.AppointmentService
import fr.rdvmedecins.client.core.services.SettingsService
import okhttp3.OkHttpClient
import java.util.concurrent.TimeUnit

class RdvMedecinsApplication : Application() {

    // lateinit: estas propriedades não nulas serão inicializadas em
    // onCreate(), e não no construtor (veja o curso de Kotlin)
    lateinit var settings: SettingsService
        private set
    lateinit var auth: AuthService
        private set
    lateinit var api: AppointmentService
        private set
    lateinit var translations: TranslationsService
        private set

    // chamado pelo Android quando a aplicação inicia, antes de qualquer tela
    override fun onCreate() {
        super.onCreate()

        // as preferências da aplicação: um pequeno arquivo privado de chave/valor
        // que sobrevive à parada da aplicação - o equivalente ao
        // localStorage de um navegador
        val prefs = getSharedPreferences("rdvmedecins", Context.MODE_PRIVATE)

        // 1. SettingsService primeiro: os outros dependem dele
        settings = SettingsService(prefs)

        // 2. um cliente HTTP OkHttp "simples", usado por AuthService para
        //    POST /login. Timeouts curtos: no mobile, uma mensagem de erro rápida
        //    é melhor que uma espera sem fim se o servidor estiver
        //    inacessível (URL errada, Wi-Fi desligado...).
        val plainHttp = OkHttpClient.Builder()
            .connectTimeout(10, TimeUnit.SECONDS)
            .readTimeout(15, TimeUnit.SECONDS)
            .build()
        auth = AuthService(settings, prefs, plainHttp)

        // 3. o cliente HTTP autenticado: uma CÓPIA do anterior
        //    (newBuilder() reaproveita sua configuração e suas conexões),
        //    mais o interceptor que adiciona o token JWT
        val authHttp = plainHttp.newBuilder()
            .addInterceptor(AuthInterceptor(auth))
            .build()
        api = AppointmentService(authHttp, settings)

        // 4. as traduções: sem dependência dos outros serviços
        translations = TranslationsService(assets, prefs)
    }
}

    Vamos comentar este código:

    • linha 34: a classe estende [android.app.Application]. O Android cria uma única instância dela quando o processo do aplicativo é iniciado, antes de qualquer activity, e a mantém até o fim do processo;

// AppViewModel.kt
// -------------------------------------------------------------------------
// O ESTADO e a LÓGICA da tela principal: a parte "_AppRootState" do
// lib/app.dart da versão Flutter (médicos, pacientes, agenda
// exibida, erro, última busca...) e as reações às ações do
// usuário (buscar uma agenda, reservar, cancelar).
//
// Por que um ViewModel, em vez de estados locais na função
// @Composable AppRoot (veja App.kt)? Porque a Activity é destruída e
// recriada a cada rotação de tela (veja RdvMedecinsApplication): um
// estado local seria perdido - a agenda exibida sumiria à menor
// inclinação do celular. Um ViewModel (biblioteca "lifecycle" do Android Jetpack)
// SOBREVIVE a essas recriações: o Android o mantém e
// o entrega à nova Activity. Ele só é destruído quando a tela
// é abandonada de vez. O Flutter não tem esse problema: lá a rotação
// não destrói nada, apenas o tamanho da tela muda.
//
// A divisão resultante é clássica no Android: App.kt EXIBE, este
// ViewModel DECIDE e chama os serviços.

package fr.rdvmedecins.client

import android.util.Log
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.setValue
import androidx.compose.runtime.snapshotFlow
import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import fr.rdvmedecins.client.core.models.DoctorDaySchedule
import fr.rdvmedecins.client.core.models.Client
import fr.rdvmedecins.client.core.models.SlotJson
import fr.rdvmedecins.client.core.models.Doctor

import fr.rdvmedecins.client.core.services.AuthService
import fr.rdvmedecins.client.core.services.AppointmentService
import kotlinx.coroutines.CancellationException
import kotlinx.coroutines.launch

class AppViewModel(
    private val auth: AuthService,
    private val api: AppointmentService,
) : ViewModel() {

    // estado exibido por App.kt (leitura pública, escrita privada)
    var doctors by mutableStateOf<List<Doctor>>(emptyList())
        private set
    var clients by mutableStateOf<List<Client>>(emptyList())
        private set
    var schedule by mutableStateOf<DoctorDaySchedule?>(null)
        private set
    var error by mutableStateOf<String?>(null)
        private set

    // o horário em reserva: não nulo = o diálogo de reserva
    // está aberto (veja App.kt e BookingDialog.kt)
    var slotBeingBooked by mutableStateOf<SlotJson?>(null)
        private set

    // a última busca (médico + dia), para atualizar a agenda após
    // uma reserva ou um cancelamento. Nunca exibida: propriedades
    // simples bastam, sem necessidade de torná-las estados do Compose.
    private var lastDoctorId: Int? = null
    private var lastDay: String? = null

    init {
        // snapshotFlow { ... } transforma a leitura de um estado do Compose em um
        // FLOW de valores: ele emite imediatamente o valor atual de auth.isLoggedIn
        // e depois cada novo valor. É o equivalente exato do
        // "watch(() => auth.isLoggedIn, ..., { immediate: true })" do Vue.js
        // - e da assinatura addListener(...) + chamada inicial
        // que a versão Flutter precisava escrever à mão.
        // viewModelScope: as corrotinas iniciadas neste escopo são
        // canceladas automaticamente quando o ViewModel é destruído (não é mais
        // preciso o removeListener(...) do dispose() do lado Flutter).
        viewModelScope.launch {
            snapshotFlow { auth.isLoggedIn }.collect { loggedIn ->
                if (loggedIn) {
                    loadInitialLists()
                } else {
                    reset()
                }
            }
        }
    }

    // -----------------------------------------------------------------------
    // no login (ou quando uma sessão lembrada é restaurada):
    // carregamos os médicos e os pacientes de uma vez por todas. Duas
    // corrotinas separadas: as duas requisições são enviadas EM PARALELO.
    // -----------------------------------------------------------------------
    private fun loadInitialLists() {
        runSafely { doctors = api.getAllDoctors() }
        runSafely { clients = api.getAllClients() }
    }

    // -----------------------------------------------------------------------
    // no logout (botão, ou token rejeitado pelo servidor):
    // limpamos o estado de negócio, para que um novo usuário não veja, nem por um
    // instante, a agenda do usuário anterior
    // -----------------------------------------------------------------------
    private fun reset() {
        doctors = emptyList()
        clients = emptyList()
        schedule = null
        error = null
        slotBeingBooked = null
        lastDoctorId = null
        lastDay = null
    }

    // botão "Log out": basta fazer o logout do AuthService -
    // o snapshotFlow (veja init) então dispara reset()
    fun logOut() {
        auth.logOut()
    }

    // -----------------------------------------------------------------------
    // botão "View schedule" do DoctorDayPicker
    // -----------------------------------------------------------------------
    fun searchSchedule(doctorId: Int, day: String) {
        error = null
        lastDoctorId = doctorId
        lastDay = day
        loadSchedule()
    }

    // -----------------------------------------------------------------------
    // botão "Book" do ScheduleView: apenas ABRIMOS o
    // diálogo, lembrando o horário em questão. No Compose, um diálogo
    // faz parte da exibição como todo o resto: ele é
    // exibido enquanto slotBeingBooked não for nulo (veja App.kt) -
    // o mesmo princípio da prop "open" do BookingDialog.vue da
    // variante Vue.js, o oposto do showDialog(...) do Flutter.
    // -----------------------------------------------------------------------
    fun requestBooking(slot: SlotJson) {
        slotBeingBooked = slot
    }

    // botão "Cancel" (ou toque fora) do diálogo
    fun closeBooking() {
        slotBeingBooked = null
    }

    // botão "Confirm" do diálogo
    fun confirmBooking(clientId: Int) {
        val slot = slotBeingBooked ?: return
        val day = lastDay ?: return
        slotBeingBooked = null // fecha o diálogo
        runSafely {
            api.addAppointment(day, clientId, slot.id)
            loadSchedule() // o horário agora aparece ocupado
        }
    }

    // -----------------------------------------------------------------------
    // botão "Cancel" de um horário ocupado, no ScheduleView
    // -----------------------------------------------------------------------
    fun cancelAppointment(appointment: AppointmentJson) {
        runSafely {
            api.deleteAppointment(appointment.id)
            loadSchedule() // o horário volta a ficar livre
        }
    }

    private fun loadSchedule() {
        val doctorId = lastDoctorId ?: return
        val day = lastDay ?: return
        runSafely { schedule = api.getDoctorScheduleOfDay(doctorId, day) }
    }

    // -----------------------------------------------------------------------
    // executa [action] em uma corrotina do ViewModel e transforma qualquer
    // exceção em uma mensagem de erro exibida na tela. Fatorar este
    // try/catch evita repeti-lo em cada método acima.
    // Uma CancellationException NÃO é um erro: é o sinal de cancelamento
    // de uma corrotina (ViewModel destruído), que deve ser deixado
    // propagar.
    // -----------------------------------------------------------------------
    private fun runSafely(action: suspend () -> Unit) {
        viewModelScope.launch {
            try {
                action()
            } catch (e: CancellationException) {
                throw e
            } catch (e: Exception) {
                Log.w("RdvMedecins", "a server call failed", e) // veja o Logcat
                error = e.message ?: e.toString()
            }
        }
    }
}

    • linha 59: [slotBeingBooked]—o horário que está sendo agendado no momento. Se for diferente de [null], a caixa de diálogo de agendamento é exibida;
    • linhas 65–66: a pesquisa mais recente (médico e dia), usada para atualizar o calendário após um agendamento ou cancelamento. São simples propriedades privadas: nunca são exibidas;

// -------------------------------------------------------------------------
// Todas as respostas de negócio do servidor NestJS têm o mesmo formato:
//
//     { "status": 0, "data": ... }
//
// onde status é 0 em caso de sucesso (veja ResponseStatus no lado do servidor).
// A versão Flutter decodificava esse envelope com uma classe genérica
// ServerResponse<T>. Aqui procedemos em DUAS etapas, por um motivo específico: em caso
// de erro, o servidor coloca uma lista de mensagens em "data"
// (List<String>) onde, em caso de sucesso, esperamos por exemplo uma agenda.
// Decodificar {status, data} diretamente como ServerResponse<DoctorDaySchedule>
// falharia, portanto, em uma resposta de erro, antes mesmo de ler o status.
//   1. lemos o envelope como uma árvore JSON genérica (JsonObject);
//   2. verificamos status; somente se for 0 decodificamos "data" no

package fr.rdvmedecins.client.core.models

import kotlinx.serialization.DeserializationStrategy
import kotlinx.serialization.json.Json
import kotlinx.serialization.json.JsonNull
import kotlinx.serialization.json.int
import kotlinx.serialization.json.jsonObject
import kotlinx.serialization.json.jsonPrimitive

// a configuração JSON compartilhada por todo o cliente:
// - ignoreUnknownKeys: o servidor envia campos que este cliente
//   não usa (p. ex. o "version" de um médico) - nós os ignoramos em vez de
//   lançar uma exceção;
// - explicitNulls = false: na codificação, uma propriedade nula não é
//   escrita (sem efeito nas classes deste cliente, mas mais próximo do
//   comportamento de JSON.stringify no lado JavaScript).
val ApiJson = Json {
    ignoreUnknownKeys = true
    explicitNulls = false
}

// exceção lançada quando o servidor responde com um status de negócio
// diferente de 0 (recurso não encontrado, data inválida, erro do servidor)
class ResponseException(val status: Int) :
    Exception("The server responded with error status $status")

// decodifica o corpo de uma resposta {status, data} e retorna "data" no
// tipo T descrito por [deserializer] (p. ex. Doctor.serializer(), ou
// ListSerializer(Doctor.serializer()) para uma lista de médicos)
fun <T> decodeResponse(body: String, deserializer: DeserializationStrategy<T>): T {
    // 1. o envelope, como uma árvore JSON genérica
    val envelope = ApiJson.parseToJsonElement(body).jsonObject
    // 2. o status de negócio
    val status = envelope.getValue("status").jsonPrimitive.int
    if (status != 0) {
        throw ResponseException(status)
    }
    // 3. "data", decodificado somente agora, no tipo esperado
    val data = envelope["data"] ?: JsonNull
    return ApiJson.decodeFromJsonElement(deserializer, data)
}

    • linha 43: [ResponseException]—a exceção lançada quando o servidor responde com um status de negócio diferente de 0;
    • Linha 49: [decodeResponse(body, deserializer)] - uma função genérica: o parâmetro [deserializer] (por exemplo, [Doctor.serializer()], gerado pelo plugin) especifica o tipo [T] no qual decodificar [data];
    • Linhas 51–59: a decodificação ocorre em DUAS etapas. Primeiro, o envelope é lido como uma árvore JSON genérica ([JsonObject]); depois, somente se [status] for 0, [data] é decodificado no tipo esperado. Motivo: em caso de erro, o servidor coloca uma lista de mensagens em [data], ao passo que, em caso de sucesso, espera-se, por exemplo, um calendário. Decodificar o envelope inteiro no tipo de sucesso logo de início falharia diante de uma resposta de erro, antes mesmo de se poder ler o status.

package fr.rdvmedecins.client.core.services

import android.content.SharedPreferences
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.setValue
import androidx.core.content.edit
import fr.rdvmedecins.client.core.models.ApiJson
import fr.rdvmedecins.client.core.models.LoginRequest
import fr.rdvmedecins.client.core.models.LoginResult
import fr.rdvmedecins.client.core.models.Role
import fr.rdvmedecins.client.core.models.decodeResponse
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext
import okhttp3.MediaType.Companion.toMediaType
import okhttp3.OkHttpClient
import okhttp3.Request
import okhttp3.RequestBody.Companion.toRequestBody
import java.io.IOException

class AuthService(
    private val settings: SettingsService,
    private val prefs: SharedPreferences,
    // um cliente HTTP SEM o interceptor de autenticação: POST /login
    // é a única rota pública do servidor, não há token a
    // enviar (veja RdvMedecinsApplication)
    private val http: OkHttpClient,
) {
    // estado da sessão, observado pela UI
    var isLoggedIn by mutableStateOf(false)
        private set
    var login by mutableStateOf<String?>(null)
        private set
    var name by mutableStateOf<String?>(null)
        private set
    var role by mutableStateOf<Role?>(null)
        private set

    // o token nunca é EXIBIDO: não é preciso torná-lo um estado do Compose.
    // Ele é porém lido por AuthInterceptor em uma thread de rede:
    // @Volatile garante que essa thread sempre veja o último valor
    // escrito pela thread principal.
    @Volatile
    var accessToken: String? = null
        private set

    // propriedade calculada: relê role a cada acesso (e, quando lida durante
    // uma exibição, inscreve a exibição nas mudanças de role)
    val isAdmin: Boolean
        get() = role == Role.ADMIN

    init {
        restoreSession()
    }

    // -----------------------------------------------------------------------
    // relê uma sessão possivelmente armazenada durante uma inicialização anterior
    // -----------------------------------------------------------------------
    private fun restoreSession() {
        val raw = prefs.getString(SESSION_KEY, null) ?: return // nenhuma sessão armazenada
        try {
            // a sessão foi armazenada como um LoginResult
            // serializado em JSON (veja logIn): nós a relemos como está
            applySession(ApiJson.decodeFromString(LoginResult.serializer(), raw))
        } catch (e: Exception) {
            // conteúdo ilegível (p. ex. o formato de uma versão antiga da
            // aplicação): nós o esquecemos, o usuário fará login de novo
            prefs.edit { remove(SESSION_KEY) }
        }
    }

    // -----------------------------------------------------------------------
    // POST /login. "suspend": esta função pode pausar pelo
    // tempo que o servidor levar para responder, SEM bloquear a thread chamadora -
    // o equivalente a uma função async que retorna um Future<LoginResult>
    // no lado Dart. Ela lança uma exceção se o login falhar.
    // -----------------------------------------------------------------------
    suspend fun logIn(login: String, password: String): LoginResult {
        // withContext(Dispatchers.IO): o bloco executa em uma thread
        // reservada para entrada/saída. O Android PROÍBE qualquer acesso à rede
        // a partir da thread principal (NetworkOnMainThreadException): ela é
        // quem desenha a UI, nunca deve esperar.
        val result = withContext(Dispatchers.IO) {
            val body = ApiJson.encodeToString(LoginRequest.serializer(), LoginRequest(login, password))
            val request = Request.Builder()
                .url("${settings.apiBaseUrl}/login")
                .post(body.toRequestBody(JSON_TYPE))
                .build()
            // execute(): uma chamada BLOQUEANTE - inofensiva aqui, estamos em uma thread
            // de entrada/saída. use { } fecha a resposta ao final do
            // bloco, aconteça o que acontecer (o equivalente ao
            // try-with-resources do Java, veja o curso de Kotlin).
            http.newCall(request).execute().use { response ->
                // credenciais erradas: o servidor responde 401 Unauthorized
                if (!response.isSuccessful) {
                    throw IOException("Login failed (HTTP ${response.code})")
                }
                decodeResponse(response.body!!.string(), LoginResult.serializer())
            }
        }
        // de volta à thread do chamador (a thread principal):
        // é aqui, e não na thread de entrada/saída, que modificamos o
        // estado observado pela UI
        applySession(result)
        prefs.edit { putString(SESSION_KEY, ApiJson.encodeToString(LoginResult.serializer(), result)) }
        return result
    }

    // -----------------------------------------------------------------------
    // logout: esquecemos a sessão, em memória e nas preferências.
    // Deve ser chamado na thread principal (veja AuthInterceptor).
    // -----------------------------------------------------------------------
    fun logOut() {
        accessToken = null
        login = null
        name = null
        role = null
        isLoggedIn = false
        prefs.edit { remove(SESSION_KEY) }
    }

    private fun applySession(session: LoginResult) {
        accessToken = session.accessToken
        login = session.login
        name = session.name
        role = session.role
        isLoggedIn = true
    }

    companion object {
        private const val SESSION_KEY = "rdvmedecins.session"
        private val JSON_TYPE = "application/json; charset=utf-8".toMediaType()
    }
}

    • linhas 51–57: o estado da sessão, como observado pela interface: [isLoggedIn], [login], [name], [role];

    • linhas 73–85: o bloco [init] restaura qualquer sessão em cache assim que o serviço é inicializado: as preferências são lidas de forma síncrona. A sessão é armazenada como um [LoginResult] serializado em JSON, que é então relido com [decodeFromString(LoginResult.serializer(), raw)];

class AppointmentService(
    private val http: OkHttpClient,
    private val settings: SettingsService,

    // -----------------------------------------------------------------------
    // as rotas GET
    // -----------------------------------------------------------------------
    suspend fun getAllDoctors(): List<Doctor> =
        call(getRequest("/getAllDoctors"), ListSerializer(Doctor.serializer()))

    suspend fun getAllClients(): List<Client> =
        call(getRequest("/getAllClients"), ListSerializer(Client.serializer()))

    suspend fun getDoctorScheduleOfDay(doctorId: Int, day: String): DoctorDaySchedule =
        call(getRequest("/getDoctorScheduleOfDay/$doctorId/$day"), DoctorDaySchedule.serializer())

    // -----------------------------------------------------------------------
    // as rotas POST (reservadas ao papel ADMIN pelo servidor)
    // -----------------------------------------------------------------------
    suspend fun addAppointment(day: String, clientId: Int, slotId: Int): AppointmentJson {
        val body = ApiJson.encodeToString(
            AddAppointmentRequest.serializer(),
            AddAppointmentRequest(day, clientId, slotId),
        )
        return call(postRequest("/addAppointment", body), AppointmentJson.serializer())
    }

    suspend fun deleteAppointment(appointmentId: Int) {
        val body = ApiJson.encodeToString(DeleteAppointmentRequest.serializer(), DeleteAppointmentRequest(appointmentId))
        // "data" é null em caso de sucesso: nós o decodificamos como um elemento
        // JSON qualquer e o ignoramos
        call(postRequest("/deleteAppointment", body), JsonElement.serializer())
    }

    // -----------------------------------------------------------------------
    // construção das requisições
    // -----------------------------------------------------------------------

        Request.Builder().url(settings.apiBaseUrl + path).get().build()

    private fun postRequest(path: String, jsonBody: String): Request =
        Request.Builder()
            .url(settings.apiBaseUrl + path)
            .post(jsonBody.toRequestBody(JSON_TYPE))
            .build()

    // resposta {status, data}. O parâmetro genérico <T> e o
    // [deserializer] que o acompanha indicam em qual tipo decodificar
    // "data" - o papel do parâmetro parseData da versão Flutter.

// por falta de um mecanismo de interceptação no pacote http. O OkHttp, por outro lado,

package fr.rdvmedecins.client.core.http

import android.os.Handler
import android.os.Looper
import fr.rdvmedecins.client.core.services.AuthService
import okhttp3.Interceptor
import okhttp3.Response

class AuthInterceptor(private val auth: AuthService) : Interceptor {

    // um Handler ligado à thread principal: ele nos permite repassar-lhe
    // trabalho a partir de outra thread (veja intercept abaixo)
    private val mainThread = Handler(Looper.getMainLooper())

    // chamado pelo OkHttp para CADA requisição, em uma thread de rede
    override fun intercept(chain: Interceptor.Chain): Response {
        // 1. a requisição original, mais o token, se houver. Uma
        //    requisição OkHttp é imutável: newBuilder() faz dela uma cópia
        //    modificável.
        val token = auth.accessToken
        val request = if (token == null) {
            chain.request()
        } else {
            chain.request().newBuilder()
                .header("Authorization", "Bearer $token")
                .build()
        }
        // 2. deixamos a requisição seguir seu caminho até o servidor
        val response = chain.proceed(request)
        // 3. token rejeitado: fazemos o logout do usuário. Este método
        //    executa em uma thread de rede; porém logOut() modifica o
        //    estado exibido pela UI: então repassamos essa chamada à
        //    thread principal (post), sem esperar que ela execute - o
        //    equivalente ao unawaited(auth.logOut()) da versão Flutter.
        if (response.code == 401) {
            mainThread.post { auth.logOut() }
        }
        return response
    }
}

    Vamos comentar este código:

    • Linha 26: a classe implementa a interface [okhttp3.Interceptor]. O OkHttp faz cada requisição passar pelos interceptors do cliente antes de enviá-la, e cada resposta antes de devolvê-la ao chamador: é o conceito dos interceptors HTTP do Angular. A versão Flutter, sem esse mecanismo no pacote [http], encapsulava o cliente HTTP em uma classe própria;
    • linha 30: um [Handler] associado à thread principal ([Looper.getMainLooper()]): isso permite delegar trabalho a ela a partir de outra thread;
    • linhas 41–43: uma requisição OkHttp é IMUTÁVEL; [newBuilder()] cria uma cópia modificável dela, acrescida do cabeçalho [Authorization];
    • linha 46: [chain.proceed(request)]—a requisição segue para o servidor; o método retorna a resposta;
    • linhas 52–53: token rejeitado (401): [intercept] é executado em uma thread de rede, mas [logOut()] modifica o estado exibido. A chamada é, portanto, delegada à thread principal ([post { ... }]), sem esperar pela execução—o equivalente de [unawaited(auth.logOut())] na versão Flutter.

// (inglês) e res/values-fr/strings.xml (francês), com o sistema
// escolhendo o arquivo certo conforme o idioma do CELULAR. Este documento
// mantém os dicionários JSON compartilhados por todas as variantes do curso,
// e a troca FR/EN dentro da própria aplicação, como fazia a

package fr.rdvmedecins.client.core.i18n

import android.content.SharedPreferences
import android.content.res.AssetManager
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.setValue
import androidx.core.content.edit
import fr.rdvmedecins.client.core.models.ApiJson
import kotlinx.serialization.json.JsonElement
import kotlinx.serialization.json.JsonObject
import kotlinx.serialization.json.JsonPrimitive
import kotlinx.serialization.json.jsonObject

class TranslationsService(
    private val assets: AssetManager,
    private val prefs: SharedPreferences,
) {
    // o idioma exibido: um estado do Compose. Como t(...) abaixo LÊ
    // esta propriedade, qualquer texto exibido com t(...) é automaticamente
    // reexibido quando o idioma muda - sem context.watch<...>() a
    // escrever, ao contrário da versão Flutter.
    var currentLanguage by mutableStateOf(prefs.getString(LANGUAGE_KEY, null) ?: DEFAULT_LANGUAGE)
        private set

    // os dicionários já carregados, por idioma ("fr" -> {...})
    private val dictionaries = mutableMapOf<String, JsonObject>()

    fun changeLanguage(language: String) {
        if (language == currentLanguage) {
            return
        }
        dictionary(language) // carrega o dicionário ANTES de mudar o idioma
        currentLanguage = language
        prefs.edit { putString(LANGUAGE_KEY, language) }
    }

    // -----------------------------------------------------------------------
    // t("LOGIN.TITLE"): percorre o dicionário do idioma atual
    // segmento por segmento ("LOGIN", depois "TITLE"). Se a chave não
    // for encontrada, a própria chave é retornada: o texto ausente permanece assim
    // visível na tela, sem derrubar a aplicação.
    // -----------------------------------------------------------------------
    fun t(key: String): String {
        var currentValue: JsonElement = dictionary(currentLanguage)
        for (segment in key.split('.')) {
            currentValue = (currentValue as? JsonObject)?.get(segment) ?: return key
        }
        val primitive = currentValue as? JsonPrimitive
        return if (primitive != null && primitive.isString) primitive.content else key
    }

    // -----------------------------------------------------------------------
    // o dicionário de um idioma, carregado na primeira vez em que é necessário e depois mantido
    // em memória. getOrPut: retorna o valor associado à chave, ou executa
    // o bloco, armazena seu resultado e o retorna. A leitura é
    // síncrona: os dois arquivos têm apenas algumas centenas de
    // bytes, lê-los é instantâneo.
    // -----------------------------------------------------------------------
    private fun dictionary(language: String): JsonObject =
        dictionaries.getOrPut(language) {
            assets.open("i18n/$language.json").bufferedReader().use { reader ->
                ApiJson.parseToJsonElement(reader.readText()).jsonObject
            }
        }

    companion object {
        private const val LANGUAGE_KEY = "rdvmedecins.language"
        private val DEFAULT_LANGUAGE = if (java.util.Locale.getDefault().language == "fr") "fr" else "en"
    }
}

    Vamos comentar este código:

    • Linhas 43–44: [currentLanguage]—um estado observável. Como [t(...)] LÊ essa propriedade, qualquer função @Composable que exiba texto com [t(...)] é recomposta automaticamente quando o idioma muda: não é necessário escrever nenhum [context.watch<...>()];
    • linhas 49–55: [changeLanguage(...)]—carrega o dicionário ANTES de trocar de idioma, depois salva a seleção nas preferências;
    • Linhas 64–70: [t("LOGIN.TITLE")]—percorre o dicionário segmento por segmento. [as?] é a conversão de tipo “segura” do Kotlin: ela retorna [null] (em vez de lançar uma exceção) se o objeto não for do tipo solicitado; combinada com [?: return key], faz com que a própria chave seja retornada assim que um segmento não puder ser encontrado—o texto ausente permanece visível na tela;
    • linhas 80–83: [dictionary(language)] – [getOrPut] retorna o dicionário já carregado ou executa o bloco (leitura de [assets/i18n/<language>.json]), armazena o resultado e o retorna. A leitura é síncrona: os dois arquivos têm apenas algumas centenas de bytes.

import androidx.compose.foundation.layout.fillMaxWidth

import androidx.compose.runtime.Composable

// as APIs ExposedDropdownMenu* ainda são marcadas como "experimental" pelo
// Material 3: @OptIn declara que as usamos conscientemente
@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun <T> DropdownList(
    label: String,
    placeholder: String,     // texto exibido enquanto nada for escolhido
    items: List<T>,
    selectedId: Int?,        // id do item escolhido, ou null
    idOf: (T) -> Int,
    itemLabel: (T) -> String,
    onSelect: (Int) -> Unit,
    modifier: Modifier = Modifier,
) {
    // menu aberto ou fechado: um estado LOCAL a esta função, lembrado de uma
    // exibição para a seguinte por remember (veja o capítulo 3)
    var menuOpen by remember { mutableStateOf(false) }
    val selected = items.firstOrNull { idOf(it) == selectedId }

    ExposedDropdownMenuBox(
        expanded = menuOpen,
        onExpandedChange = { menuOpen = it },
        modifier = modifier,
    ) {
        // o campo que exibe a escolha atual; menuAnchor(...) o torna o
        // ponto de ancoragem do menu (um clique nele abre o menu)
        OutlinedTextField(
            value = selected?.let(itemLabel) ?: "",
            onValueChange = {},
            readOnly = true,
            singleLine = true,
            label = { Text(label) },
            placeholder = { Text(placeholder) },
            trailingIcon = { ExposedDropdownMenuDefaults.TrailingIcon(expanded = menuOpen) },
            modifier = Modifier
                .menuAnchor(ExposedDropdownMenuAnchorType.PrimaryNotEditable)
                .fillMaxWidth(),
        )
        // o próprio menu: um DropdownMenuItem por item
        ExposedDropdownMenu(expanded = menuOpen, onDismissRequest = { menuOpen = false }) {
            items.forEach { item ->
                DropdownMenuItem(
                    text = { Text(itemLabel(item)) },
                    onClick = {
                        onSelect(idOf(item))
                        menuOpen = false
                    },
                )
            }
        }
    }
}

    Vamos detalhar este código:

    • linhas 38–46: [fun <T> DropdownList(...)]—uma função @Composable GENÉRICA: ela exibe tanto médicos quanto pacientes. [idOf] especifica como identificar um elemento, [itemLabel] como exibi-lo e [onSelect] indica o identificador escolhido;
    • linha 46: [modifier: Modifier = Modifier]—a convenção do Compose: todo componente reutilizável aceita um modifier, aplicado ao seu elemento raiz, para que o chamador possa ajustar seu tamanho ou suas margens;
    • linha 50: [var menuOpen by remember { mutableStateOf(false) }]—o estado local do componente: menu aberto ou fechado;
    • linha 53: [ExposedDropdownMenuBox]—o contêiner, que gerencia a abertura e o fechamento do menu;

    • linhas 73–79: o próprio menu: um [DropdownMenuItem] por item, gerado por um laço [forEach].

@Composable
fun LoginPage() {
    val auth = LocalAuth.current
    val t = LocalTranslations.current::t

    // estado local da tela
    // rememberSaveable: o valor é lembrado de uma exibição para a seguinte
    // E sobrevive à recriação da Activity (rotação de tela) - um
    // login pela metade não se perde se o celular for girado.
    var login by rememberSaveable { mutableStateOf("") }
    var password by rememberSaveable { mutableStateOf("") }
    // a chave de tradução da mensagem de erro (e não a mensagem traduzida:
    // assim ela acompanha uma mudança de idioma), ou null
    var error by rememberSaveable { mutableStateOf<String?>(null) }
    // somente remember: um login em andamento não precisa sobreviver a uma rotação
    var inProgress by remember { mutableStateOf(false) }

    // um escopo de corrotinas ligado a esta tela: as corrotinas
    // iniciadas nele são canceladas se a tela desaparecer
    val scope = rememberCoroutineScope()

    // uma função local (veja o curso de Kotlin): a validação do
    // formulário, chamada pelo botão E pela tecla "Done" do teclado
    fun submit() {
        if (login.isBlank() || password.isEmpty() || inProgress) {
            return
        }
        error = null
        inProgress = true
        scope.launch {
            try {
                // em caso de sucesso, AuthService define isLoggedIn como true:
                // App.kt então substitui AUTOMATICAMENTE esta tela pela
                // agenda - nada mais a fazer aqui
                auth.logIn(login.trim(), password)
            } catch (e: CancellationException) {
                throw e
            } catch (e: Exception) {
                // a causa exata (servidor inacessível, credenciais erradas...)
                // é escrita no log do Android (aba Logcat do Android
                // Studio); o usuário vê uma mensagem simples
                Log.w("RdvMedecins", "login failed", e)
                error = "LOGIN.ERROR"
            } finally {
                inProgress = false
            }
        }
    }

    // Box + Alignment.TopCenter: o card fica centralizado horizontalmente
    Box(modifier = Modifier.fillMaxWidth(), contentAlignment = Alignment.TopCenter) {
        Card(modifier = Modifier.widthIn(max = 420.dp).fillMaxWidth()) {
            Column(
                modifier = Modifier.padding(24.dp),
                verticalArrangement = Arrangement.spacedBy(12.dp),
            ) {
                Text(t("LOGIN.TITLE"), style = MaterialTheme.typography.titleLarge)

                error?.let { key ->
                    Surface(
                        color = MaterialTheme.colorScheme.errorContainer,
                        contentColor = MaterialTheme.colorScheme.onErrorContainer,
                        shape = RoundedCornerShape(4.dp),
                        modifier = Modifier.fillMaxWidth(),
                    ) {
                        Text(t(key), modifier = Modifier.padding(8.dp))
                    }
                }

                OutlinedTextField(
                    value = login,
                    onValueChange = { login = it },
                    label = { Text(t("LOGIN.LOGIN_LABEL")) },
                    singleLine = true,
                    // tecla "Next" do teclado: passa para o próximo campo
                    keyboardOptions = KeyboardOptions(imeAction = ImeAction.Next),
                    modifier = Modifier.fillMaxWidth(),
                )

                OutlinedTextField(
                    value = password,
                    onValueChange = { password = it },
                    label = { Text(t("LOGIN.PASSWORD_LABEL")) },
                    singleLine = true,
                    // exibe pontos no lugar dos caracteres
                    visualTransformation = PasswordVisualTransformation(),
                    keyboardOptions = KeyboardOptions(
                        keyboardType = KeyboardType.Password,
                        imeAction = ImeAction.Done,
                    ),
                    // tecla "Done" do teclado: envia o formulário
                    keyboardActions = KeyboardActions(onDone = { submit() }),
                    modifier = Modifier.fillMaxWidth(),
                )

                Spacer(Modifier.height(4.dp))
                Button(
                    onClick = { submit() },
                    enabled = !inProgress,
                    modifier = Modifier.fillMaxWidth(),
                ) {
                    Text(if (inProgress) t("LOGIN.SUBMITTING") else t("LOGIN.SUBMIT"))
                }

                Text(
                    text = "${t("LOGIN.DEMO_ACCOUNTS_PREFIX")} admin / admin ${t("LOGIN.DEMO_ACCOUNTS_ADMIN")} " +
                        "${t("LOGIN.DEMO_ACCOUNTS_OR")} user / user ${t("LOGIN.DEMO_ACCOUNTS_USER")}.",
                    style = MaterialTheme.typography.bodySmall,
                )
            }
        }
    }
}

        )
    }

            // botão desabilitado enquanto nenhum médico for escolhido
